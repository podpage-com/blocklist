Blocklist

Shared infrastructure for exchanging IP abuse observations between independent organizations.

Blocklist distributes information. It does not make blocking decisions or manage participant infrastructure.

Integration

Every organization receives an API key. Send it as Authorization: Api-Key YOUR_KEY.

Report an observation

POST /api/v1/observations/
{
  "ip_address": "203.0.113.42",
  "reason": "signup_abuse",
  "last_seen_at": "2026-09-18T05:00:00Z"
}

Synchronize your complete current list

PUT /api/v1/observations/sync/
{
  "observations": [
    {"ip_address":"203.0.113.42","reason":"spam"},
    {"ip_address":"198.51.100.7","reason":"scraping"}
  ]
}

The sync endpoint is authoritative: observations previously published by your organization but absent from the request become inactive.

Read API

EndpointPurpose
GET /api/v1/observations/Current active observations
GET /api/v1/ips/<ip>/Reports and reasons for one IP
GET /api/v1/changes/?since=...Incremental changes
GET /health/Service health

Observation queries support ?ip=, ?reason=, and ?organization=.

Consumer policy

A participant may block every reported address, require reports from multiple organizations, use observations only as a risk signal, maintain local allowlists, or ignore categories it does not care about. That policy belongs to the participant.
